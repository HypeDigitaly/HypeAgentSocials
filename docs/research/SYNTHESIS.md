## 1. Consolidated resolved recommendations, by pipeline area

The canonical stage order, resolved across C3 (orchestration), C6 (brand truth first), C4 (cost gate before spend) and A2 (async media):

Theme load → brand-truth resolution → **brand-truth gate** → collection → ranking → **fit gate** → spin → copy generation → **spin gate** → **claim gate pass 1** → **voice gate** → **claim gate pass 2** → **platform gate** → media planning (always produced) → **cost gate** → media generation (async, may span runs) → assembly → packaging → notification → **human review gate** → **publish gate** → distribution prep

Brand truth resolves *before* research because the degrade decision changes what the rest of the run is allowed to do, and a research-only run must not have paid for anything before finding that out (C6 §6.1). Media planning is always produced even at zero budget (assignment rule, A2 Tier 0), so a plan-only run is a complete, useful run.

### 1.2 Extraction (methods and mechanics)

**Resolved (B2, hardened by C7).** Method vocabulary is fixed: official API, feed, licensed vendor, auth-integration, MCP wrapper, operator input, skip. **Playwright appears nowhere in the v1 collection path.** Every List A surface is either officially open (use the API), officially closed and technically defended (do not scrape), or reachable by plain HTTP feed where a browser adds nothing. The do-not-scrape list is binding in every mode including degraded ones: Reddit (any surface), X, LinkedIn (any surface), Meta web surfaces including the Ad Library UI, TikTok, Google SERP and Trends UI, G2-class review sites, any login wall, any surface serving an anti-bot challenge, any robots-disallowed path. Absence from the list is not permission — new sources enter through the method-evaluation gate.

Fallback ladders are primary → degraded → operator-supplied → skip-with-log, and no rung ever falls through to scraping. Unattended mechanics: window-keyed idempotent runs, single-holder lease, append-only writes under natural keys, cursor pagination with snapshot-then-detail, per-source circuit breakers, a global wall-clock ceiling so ranking and packaging always run on whatever was gathered. All collected text is untrusted, adversarial input carried as quoted data with provenance tags — never as instructions to a downstream model.

Storage: request log always (12 months), raw payloads briefly (30 days, adopting YouTube's refresh-or-delete rule as the global default), normalised signal records 90 days, provenance snapshots permanent with the pack (links plus short excerpts, never payloads). Targeted deletion by canonical key must exist from day one.

**Resolved addition (B5) — "MCP source" becomes a first-class connector class.** The method vocabulary gains a properly-specified member. Both licensed vendors in the revised portfolio speak MCP with bearer-key or credential auth rather than interactive OAuth, which means they are cron-compatible without a browser — the exact property that disqualified Notion's hosted MCP for unattended brand truth (C1). So the collector layer standardises on **MCP as the integration idiom for licensed data** (Virlo for short-form trends, DataForSEO for search demand) and reserves bespoke collectors for the free open APIs and feeds. Two mechanics the MCP-source connector must handle, both of which fit B2's existing discipline: **async job semantics** (Virlo auto-polls for about 25 seconds then returns a job id, which maps onto snapshot-then-detail and the per-source circuit breaker) and **credit metering as a first-class budget** — reads of already-computed results are free, which rewards precisely the cache-before-call rule B2 mandates, while a niche-monitor run or keyword search costs real credits and must be paced against a monthly allowance the same way media spend is. B2's rule that an MCP wrapper is only acceptable when it fronts a legitimate method still governs: what makes these two acceptable is that they are licensed vendors selling *derived analytics under terms that permit pipeline use*, not raw scraped passthrough.

**Open.** Whether a licensed SERP/Trends vendor is used at all (see §3.9 — C7's finding that Google's Custom Search JSON API is closed to new customers materially softens B2's vendor recommendation). Exact retention numbers pending legal sign-off. The gray-market gateway exclusion is confirmed as a working assumption but never formally ratified.

### 1.3 Ranking

**Resolved (B3, re-derived in §2a).** Four dimensions — attention/virality, brand fit, freshness, confidence/availability weight — combined **multiplicatively**, so a near-zero brand fit cannot be outvoted by high virality. Two independent gates before ranking: a numeric floor on brand fit alone (directional default 0.35) and a binary veto list (legal/claim-risk, competitor disparagement, high-severity controversy, detected manipulation, prompt-injection). Seven negative brand-fit criteria with a rules-first/LLM-second split. Every candidate carries an inspectable scorecard with sub-scores, bands, one-line rationales, evidence-quality label and the ranking-config version. The brand-fit judgment must produce a falsifiable verdict — state the honest connection in one sentence or fail. Fail-closed if the judgment step itself fails. Per-language decisions are first-class (generate / skip / hold per language), never one global decision plus translation. Thresholds are never relaxed to manufacture volume; a run producing zero passing candidates is correct behaviour.

**Open.** All numeric values (floor, half-lives, top-N caps, corroboration bonus magnitude) pending real run data. Whether a cs-only/en-only hold list is built in v1. Where semantic topic clustering technically lives. Whether automatic threshold recalibration is ever enabled (recommended: no).

### 1.4 Brand truth

**Resolved (C6, with C1's tool-surface facts, re-derived in §2d).** Fourteen fact classes in three tiers — blocking, constraining, enriching — with the governing rule that **missing is not the same as empty**: every constraining class resolves to *resolved-with-values*, *resolved-empty* (safe, generative) or *unresolved* (failure). Precedence is per fact class, not one flat order: the live site wins on commercially binding facts (prices, trial terms, plan contents, guarantees, offer availability), Notion wins on internal knowledge, config wins on design artefacts (voice rules, CTA selection, pricing policy). Three asymmetries are load-bearing: excludes are monotonic, the site can subtract but never add a claim, and silence is not agreement while an unreadable source is not disagreement. Conflicts resolve three ways — resolvable, degrade-to-narrower, or red-flag stop with no tie-breaking permitted on the commercially binding set.

Confidence is computed gate-first then scored, per (theme, language), into four coarse bands — FULL, PARTIAL, MINIMAL, INSUFFICIENT — each with an explicit capability table. The unattended degrade trigger is exact: below PARTIAL, or any unresolved red-flag conflict, or an expired/invalid offline snapshot, or an unreadable claim ledger, or unresolved hard excludes. Every pack carries a hashed brand-truth snapshot plus a **fact-usage trace** so the operator can later ask "we corrected the trial length — which packs are affected?" Human overrides may narrow but may never create commercial facts.

**Open.** Whether the claim ledger lives in Notion, config, or split (recommendation in §7). Exact freshness thresholds and max-offline window. Whether an operator may raise the band ceiling interactively when offline (recommendation: no).

### 1.5 Text generation and voice

**Resolved (C5, A3, C6).** A five-layer anti-slop stack, cheapest first: lexicon screen (deterministic banned phrases plus a cross-pack recurrence check for the system's own house tics) → structural heuristics (sentence-length variance, em-dash density, bullet vagueness, opener repetition) → LLM judge against the rubric → bounded regenerate with the judge's diagnosis fed back → escalate to review, labelled, never silently shipped and never silently dropped. The judge is a different call and ideally a different model lineage from the generator. The **spin gate is architecturally separate from the voice gate** because their repairs differ: a spin failure means drop the offer, a voice failure means rewrite the phrasing. Spin has two checkpoints — angle-level pre-check before drafting tokens are spent, and artifact-level post-check on the finished draft — enforced through seven binary criteria (real topic anchor, ICP addressing, connection chain, distance compliance, proof discipline, next-step correctness, no hype-glue).

Prompt architecture (A3) is a four-part anatomy repeated per artifact type: role/constraint framing → grounded inputs → generation instruction with explicit output shape → self-check rubric. Negative prompting is four composable layers — engine-visual, engine-copy-slop, theme, language — plus a fifth added in §2e (route-policy constraints from the model registry). Four skill bundles (reels/short-video, ad-creative, UGC, carousel), each holding instructions, exemplars, rubric and fallback. The engine/theme/language boundary is a three-axis overlay: language is its own axis so every future Czech theme shares one Czech lexicon rather than re-deriving it.

The English voice rubric is authored and usable now, derived from the real exemplar corpus. The Czech rubric is authored in §2c of this document. Judge calibration uses a golden set with **asymmetric** error accounting: judge-passed/human-failed (slop ships — reputational) is tuned separately from judge-failed/human-passed (regenerate storms — cost and alert fatigue).

**Open.** Per-language and per-role model selection (drafting, judge, polish) needs a live dated comparison. Regenerate cap, flag-rate ceiling, golden-set size, judge pass cutoff, structural thresholds — all need pilot data. Whether a cross-model judge-of-the-judge check earns its cost.

### 1.7 Assembly and post-production

**Resolved (A4).** A local FFmpeg-core assembly engine is the engine of record — zero marginal cost, deterministic, no network dependency, identical exit-code behaviour on both target platforms — with a cloud assembly API behind an adapter seam as an optional substitute or contingency. All message-bearing on-screen text, in **both** languages, is applied post-render with bundled brand fonts verified for full Czech glyph coverage; generative models are never asked to render message-bearing copy. Caption text always comes from the authored script verbatim; alignment (or TTS-native timestamps) supplies timing only, which makes displayed-text accuracy 100% by construction and reduces the Czech ASR gap to a timing problem rather than a content problem. Karaoke-style word reveal requires the ASS subtitle path burned via libass.

Audio: master to −14 LUFS integrated with a −1.0 dBTP ceiling, two-pass normalisation, sidechain ducking of music under voice, measured values logged per asset as a QA gate. Music must be licensed — a library subscription or a paid-plan AI music generator; platform trending audio is prohibited for the master asset. Visual: one 1080×1920 master designed inside the ≈900×1400 universal safe box, with layered re-composition (not cropping) for other ratios. End card is a two-second templated overlay with a soft CTA delivered both spoken and on-screen, plus a mid-video soft cue; a loop-friendly no-outro recipe is also supported.

**Carousel-to-reel is a first-class recipe and the default Czech video format**: every pixel of text is our own typography, the voice is proper Czech TTS or none, and no generative video model is involved — so it carries neither the F-5 spoken-claim risk nor the F-7 diacritic risk, and it reuses already-generated slide art.

Provenance: sign a C2PA manifest after the final encode, archive signed masters with the pack, and carry a per-asset publish-time disclosure flag. Never claim end-to-end provenance survival — platforms strip manifests on re-encode.

**Open.** Whether any caption-styling SaaS is added for English polish and whether any handles Czech acceptably. ElevenLabs versus Azure as primary Czech voice at production volume. FFmpeg distribution and GPL/LGPL build choice. AI outpainting for ratio conversion. AI-generated versus library music per theme. English native-audio versus TTS-everywhere. A Remotion-class premium template tier.

### 1.8 Review

**Resolved (C4, constrained by D-07 and C3).** One entry point per run — the **run digest** — scannable in about two minutes: header with run identity, counts and a prominent cost forecast; a topic table with rank, confidence band, freshness and dedupe status, brand fit and decision state; a footer linking to detail, cost breakdown and any regeneration queue. Approval is expressed either by editing a decision file in the run folder or by an interactive console command referencing the run id. See §3.11.

### 1.9 Distribution

**Resolved (C1, F-4).** Postiz is the publishing bridge, draft-first: posts are created with draft status and no schedule date, and remain untouched until a human schedules or publishes. A five-layer defence-in-depth stack: config allowlist per mode → only allowlisted channels are ever connected as Postiz integrations → a single fail-closed publish gate → Postiz's own draft state → the human approval requirement. Research-only platforms may never appear in any allowlist and are never connected as channels at all. If a channel is allowlisted but not actually connected, the run fails closed for that destination and names it in the pack — no silent skip, no silent substitution. Cloud Postiz at the $29 tier is the recommended trial vehicle; cloud and self-hosted have feature parity, and the difference is operational burden.

**Resolved gap.** Postiz does **not** expose per-platform AI-label fields — no TikTok AIGC toggle, no YouTube synthetic-media property, no Meta AI-disclosure control. The labelling step is therefore manual in v1 and belongs in the operator runbook and the pack checklist.

**Open.** Everything positive about Postiz is a paper claim — no account exists (OP-2). Draft-without-schedule must be verified on the real plan as an implementation acceptance criterion, with the fallback ladder (unscheduled draft → far-future schedule → local-only staging and manual paste) designed first-class. ### 1.10 Runtime and cron

**Resolved (C3, C2, re-derived in §2b).** A deterministic pipeline backbone with narrow, bounded LLM nodes — never an agentic loop deciding stage sequencing, budget gating or exit codes. Run identity is theme plus a pinned logical run-date (derived once from a configured theme timezone) plus an attempt number; every stored timestamp is UTC. Overlap policy is skip-on-lock, logged distinctly from both success and failure; never auto-kill a running instance, because that orphans paid in-flight media jobs. Locking is an OS-mediated exclusive file lock on both platforms plus a ledger-recorded in-progress row. Idempotency uses content-hash keys per stage. Checkpointing is per unit of work. Per-stage timeouts nest inside an overall run ceiling whose approach triggers graceful wind-down — stop starting paid work, checkpoint, package what is complete — never a hard kill. Missed runs are handled by the pipeline, not the OS scheduler: skip missed windows, run once for now, record how many were missed.

Substrate: an embedded single-file transactional store for everything structured and queryable (run ledger, spend ledger, media-job ledger, dedupe index, review decisions, snapshot metadata); plain files for bulky human-readable content (raw research artifacts, packs, brand-truth snapshot bodies). No database service to install or administer.

Secrets: permission-restricted files as the portable cross-platform baseline, with OS-native hardening layered on top, never as the sole mechanism. Secrets never enter source control, prompts, the run ledger, or logs.

Stack (C2): Python, distributed as a managed project checkout with locked dependencies and a thin per-OS launcher. Scheduled runs execute under the operator's own user account, never SYSTEM — otherwise browser installs, credential stores and per-user encryption all fail invisibly. Explicit UTF-8 everywhere, absolute paths from config, file logging as the only observability in a scheduled context, and explicit exit-code propagation from any wrapper.

Notification: a filesystem status flag as the mandatory dependency-free baseline plus one configurable push channel; a notification-delivery failure must never change the run's own exit class.

**Open.** Cadence and per-run caps. Push channel choice. Whether the Linux deployment uses bare cron or systemd timers. Numeric exit-code mapping.

### 1.11 Legal and compliance

**Resolved (C7, with A4 and C2).** EU AI Act Article 50 became binding on 2 August 2026 — four days before the briefs — with no size exemption, extraterritorial scope, and fines up to €15 million or 3% of worldwide turnover. Because platforms strip C2PA on re-encode, metadata-only compliance fails: **every AI-generated video, image and audio asset carries a burned-in, human-perceivable AI disclosure applied at render time**, and an asset without it cannot be marked publish-ready. Platform-native labels (TikTok AIGC, YouTube altered-content, Meta AI Info, a per-post LinkedIn disclosure line) are a separate, cumulative contractual obligation set at publish-prep.

Public social content is personal data under GDPR even when public; the applicable basis is legitimate interest, requiring a documented case-by-case assessment and a published privacy notice — company artefacts the architecture assumes exist rather than generates. Storage defaults to extract-first with bounded retention and hashed or dropped author handles, and must support targeted deletion on objection.

Any synthetic presenter modelled on a real identifiable person requires documented, scope-limited consent under Czech personality-rights law, independent of any AI Act or platform rule; wholly fictional personas do not, but still require labelling. Every generated asset must carry a provenance record naming the exact routed model and version, the generation timestamp, a snapshot of that model's commercial-use terms at generation time, and the router transaction id — because a router grants no rights of its own and the upstream model provider is typically a third-party beneficiary who can enforce directly against us. Czech consumer-protection law gives the never-invent-claims rule independent legal force, so the claim gate's per-asset log doubles as regulatory-defensibility documentation.

**Open.** Kie.ai's actual terms of service text (blocked from automated retrieval — pull manually before build). The exact scope of the Article 50(4) human-editorial-review carve-out as applied to synthetic-presenter video. A concrete retention-window number in days. Direct-text confirmation of the two Czech statutes cited. Whether the AI Office Code of Practice on Transparency has finalised.

### 2a. B3's ranking design, re-derived against B1's and B2's real per-source findings

B3 was written without web access and marked six categories of assumed input (§2.7): per-source engagement availability, timestamp precision, language tagging, retained history for baselines, author metadata richness, and whether collection already emits topic/entity tags. B1 and B2 have now supplied the reality. Seven things change.

**Change 1 — three evidence classes replace one virality model.** The real day-1 roster does not divide into "sources with counts" and "sources without". It divides into three:

| Evidence class | Sources (v1 roster) | What the source exposes | Virality treatment |
|---|---|---|---|
| **Counted** | Hacker News (points, comment counts, near-real-time timestamps, full history via Algolia), Product Hunt (votes, comments, createdAt), Hugging Face (likes, downloads, trending sort), Bluesky (likes/reposts/replies, indexedAt), YouTube (views, likes, comments, publishedAt) | Numeric engagement + reliable timestamps + retrievable history | Within-source percentile normalisation as B3 designed |
| **Ranked / presence-only** | Bluesky trending-topics endpoint, GitHub trending page, TikTok Creative Center lists, AI-newsletter inclusion, Google News RSS presence, Google Trends relative index | Position on a curated list, or a pre-normalised index, but no per-item counts | Presence/rank proxy with a hard confidence ceiling; never reaches the High band |
| **Human-asserted** | Reddit curated inbox, LinkedIn organic browsing, Discord/Slack communities, review-site excerpts, Ad Library observations, operator-seeded topics | Whatever the operator writes down; no machine-verifiable metric | Replaced by a coarse operator salience input, labelled distinctly and never rendered as measured virality |

Google Trends is a special member of the ranked class: its 0–100 figure is already a within-source normalisation, and B1 confirms it is *relative, not absolute*. B3's assumption here was correct but its role changes — Trends is a **demand modifier applied after ranking**, not a virality input, and at weekly manual cadence it cannot participate in daily scoring at all. Meta Ad Library is also unusual: it exposes impression ranges and delivery start times but no engagement, and B2's key insight is that **a still-running ad is proven, so age is positive signal** — the ad-creative class inverts the freshness term.

**Change 2 — corroboration must be computed across source *families*, not source instances.** B3's cross-source corroboration bonus assumed structural independence. The real roster is heavily correlated: Hacker News, the newsletters, Google News RSS, Product Hunt and Hugging Face routinely cover the same launch event within hours, and the newsletters explicitly exist as an editorial relay over the same discourse. Counting those as four independent confirmations would inflate exactly the topics that are already over-covered. Resolution: define seven source families and count corroboration only across them — (i) developer/technical discourse (HN, GitHub, Bluesky), (ii) launch registries (Product Hunt, Hugging Face), (iii) editorial relay (newsletters, Google News RSS, tech press feeds), (iv) demand (Trends, Keyword Planner), (v) ad creative (Meta Ad Library, LinkedIn Ad Library), (vi) human-curated (Reddit inbox, LinkedIn browsing, communities, operator seeds), (vii) video and packaging (YouTube, TikTok Creative Center). A newsletter relaying an HN story is the same event echoed, not a second observation.

**Change 3 — baselines are bounded, and cold start now has a date.** B3 assumed retained history for percentile normalisation. B2's retention design gives normalised signal records a 90-day life, and YouTube's developer policy forces a stricter 30-day refresh-or-delete rule on YouTube-derived metrics specifically. So the maximum trailing baseline is 90 days generally and 30 days for YouTube, and the practical default aligns with B2's 14-day dedupe window. Consequence: **for roughly the first two weeks of real operation there is no baseline at all.** Counted-class virality must therefore run in an absolute-band fallback (fixed per-source thresholds) explicitly labelled "no baseline yet", switching to percentile mode once the window fills. This remains a data-availability state, not a separate code path — B3's invariant survives.

**Change 4 — language is known by construction for most of the roster.** B3 asked whether sources tag language. Answer: Bluesky posts carry a self-declared language field; Google News RSS is language-scoped by feed construction; YouTube supports a relevance-language query parameter and sometimes exposes a default audio language; Hacker News, Product Hunt, Hugging Face, GitHub and the newsletters are English by construction; curated-inbox items inherit the operator's tag; B4's Czech venues are Czech by construction. Only mixed-language article bodies need detection. Rule: stamp language at the source level first, run per-item detection only on genuinely mixed feeds.

### 2b. C3's cron and ledger design, re-derived against A2's actual provider findings

C3 was written without web access and marked its provider assumptions explicitly. A2 has now supplied verified facts that both confirm the shape and correct one important detail. Ten guarantees the media-job ledger and checkpoint design must now provide.

**G1 — Idempotency is entirely local, and C3's phrasing must be corrected.** C3 §2.3 specified "a client-supplied idempotency token passed to the provider's job-submission call". A2 verified that **Kie documents no idempotency key, no client-reference field and no dedup semantics on task creation**, and Higgsfield's public docs are silent. There is no token to pass. The correction: the write-ahead ledger row *is* the idempotency mechanism. A deterministic asset identity — theme, run-date, topic, asset slot, language, prompt-pattern version — is committed as an intent row *before* the HTTP submission; the task id is written on acceptance; the terminal state and observed cost on resolution. On restart, an intent row without a terminal state is **resolved by querying task status**, never re-submitted blindly. One identity permits at most one paid attempt chain.

**G1a — a named ambiguous state is required.** If the process dies between committing the intent and recording the task id, the true state is unknowable: the provider may or may not have accepted and charged. The ledger needs an explicit `submitted-unknown` state, and the honest handling is **no automatic resubmission** — reconcile via balance delta, and if still unresolved, surface it to the operator as a possible orphan spend. This is the direct cost of a provider with no idempotency, and pretending otherwise is how a crash becomes a double charge.

**G2 — download-before-done, driven by an expiry-ordered queue.** A2 verified media deletion at 14 days, result URLs with validity windows, and an explicit expiry flag in at least one route family. So the state machine must be submitted → polling → completed-pending-download → **rehosted** → done, with re-hosting mandatory before an asset slot is marked complete, an integrity check (byte length plus checksum recorded in the ledger) so a truncated download is not marked done, and the **first phase of every run** being "adopt pending tasks and drain the download queue ordered by nearest expiry, before submitting anything new". Provider URLs are never the artifact of record and never appear in a pack — a pack holding provider URLs silently rots before a human reviews it.

**G3 — rate limits become a locally enforced pacing budget.** A2 verified ~20 new generation requests per 10 seconds, 100+ concurrent running tasks, HTTP 429 on violation. A single two-language pack submits roughly twenty jobs (three clips plus seven images, doubled), which can trip the limit in one burst. The submission stage must pace itself well under the ceiling (recommend no more than ten submissions per ten seconds) and treat 429 with backoff-and-jitter, never a tighter loop. Concurrency is not the binding constraint — our own wall-clock and budget are.

**G4 — the exit-code taxonomy gains two classes.** A2's async reality (renders take 1–6 minutes, 1080p adds 1–2 more, tasks can hang, a 10-minute timeout semantic exists) means **a run legitimately ends with jobs still pending**. That is healthy, not failure, and must not page cron monitoring nightly. C6 separately requires a distinct outcome for brand-truth degrade. The taxonomy therefore becomes nine classes: success; completed-with-pending-media; partial-success (degraded sources); partial-success (budget-capped mid-pack); completed-degraded (research-only); budget-stop (pre-emptive); policy-stop; skipped-overlap; hard-failure. Numeric mapping stays deferred to implementation.

**G5 — spend reconciliation must tolerate disputed billing.** A2 records that Kie claims failed tasks are not charged while community reports describe credits vanishing on stuck tasks. Kie does expose a credit-balance endpoint. So the ledger records both an **expected cost** (from the registry price snapshot) and an **observed cost** (from balance delta across the run), and "unexplained spend" is a first-class alarm. Budget caps are enforced pre-submission against expected cost — a post-submission check is too late — and a configured unexplained-spend tolerance acts as a provider-misbehaving circuit breaker that halts new submissions. This also closes C3's deferred question about billing APIs: Kie exposes a balance snapshot, not itemised billing; Higgsfield remains unknown (paper-only).

**G6 — the silent model-substitution fact forces a delivered-versus-requested record.** A2 verified that Kie's Veo route can silently switch to a backup model on some content-review triggers, and that such fallback outputs cannot use the 1080p endpoint and are forced to 16:9. This has two downstream consequences the ledger must serve. First, the pack must show that the aspect ratio and quality the plan asked for are not what arrived — otherwise a 16:9 asset silently enters a 9:16 destination and fails C2's platform gate at publish time. Second, and more seriously, **C7 requires a per-asset license snapshot of the model that actually rendered**; if a different model rendered, its rights class may differ. So the ledger stores requested route, requested aspect and requested resolution alongside delivered values, and the provenance record is resolved *after* completion, not at submission.

**G7 — refusals exit the retry loop immediately.** A2 documents synchronous refusals (400 policy, 422 moderation) and asynchronous ones (terminal fail, 501), plus a Europe-specific person-generation restriction directly relevant to a Czech operator. C3's default retry policy is backoff-with-cap for submission calls — but a policy refusal is not transient and must never enter that loop. It exits straight to the refusal ladder: one automated sanitise-and-rewrite, one model-swap to a registered alternate, then degrade to plan-only, with a hard cap of three paid attempts per asset slot. Every refusal is logged with route, trigger class and prompt-pattern version so per-route refusal rates accumulate in the model registry — no provider publishes refusal rates, so this must be measured in-house.

**G8 — the checkpoint unit is now precisely defined.** C3 chose per-unit-of-work granularity. The unit is one (asset slot × language × attempt), which is exactly one ledger row and exactly one paid attempt chain.

**G9 — the substrate choice is now evidence-backed rather than assumed.** C3 argued for a transactional embedded store for the media-job and spend ledgers "most strongly of all". A2's facts make the argument concrete: the "find jobs nearing expiry, not yet downloaded" query is provably needed at the start of every run, and balance reconciliation needs a transactional running total that cannot tear.

**G10 — polling-first is confirmed.** A cron console process has no stable public HTTPS endpoint, and A2 confirms both polling (~30-second interval) and callbacks are offered. Polling is the baseline; a webhook receiver is an optional later optimisation. Per-job poll budgets nest inside C3's per-stage timeouts, and the overall run ceiling triggers graceful wind-down: stop submitting, checkpoint in flight, package what is complete.

**One further hardening.** A2 notes Kie supports per-key rate limits and IP whitelisting. Use separate keys for development and cron, with the cron key top-up-limited, so a runaway loop is bounded by the wallet rather than only by our own code.

A2 documents provider-side realities that are neither engine-generic nor theme-specific: the EU and UK person-generation restriction (adults only, with some person image-to-video requiring allowlisting), model-level refusal of named real people, refusal on trademarks and logos in input images, and documented child-safety false positives on wholesome commercial storyboards. These belong to the *route*, so add a **route-policy constraint layer** populated automatically from the model registry's person-policy and rights classes. A theme author should never have to know that a particular route restricts person generation in Europe — the router should refuse to select an ineligible route, and the prompt composer should inject the constraint.

**R6 — the overgeneration economics resolve exactly.** A3's principle is "cheap to overgenerate text, expensive to overgenerate video". A2 quantifies the ladder: hooks and scripts are effectively free, a keyframe is about four cents, a standard clip is thirty cents, a hero clip is $1.25. So: overgenerate three to five hook candidates with a selection rubric; overgenerate two or three keyframe variants; **never overgenerate clips**. The approval event that unlocks clip spend is keyframe acceptance — which is also A2's Tier-1-to-Tier-2 escalation rule and C4's cost gate expressed at the asset level.

**R7 — the failure taxonomies merge cleanly, with one specialisation.** A3's three failure classes (soft rubric miss, refusal or provider error, hard input problem) map onto A2's refusal ladder, except that a provider policy refusal is emphatically *not* transient: it gets exactly one informed sanitise-and-rewrite, then one model swap, then plan-only degrade, capped at three paid attempts per slot. A3's rule of thumb survives unchanged and should be quoted into the architecture: retry small, degrade safely, never fabricate, always surface.

**R8 — a genuine conflict on multi-shot models, resolved.** A1 names Wan2.7, StoryDiffusion and OneStory as multi-shot-native and claims multi-shot cuts assembly from 30–40 minutes to 5–10. A2's routable roster places multi-shot capability with Kling 3.0 and classes the Wan family as budget/workhorse. A2 owns provider facts; A1's named systems are research publications, not Kie routes. Resolved: **v1 multi-shot capability is Kling 3.0 only, hero tier only.** A1's analysis of *what changes* when multi-shot is used remains valid as the conceptual description and should be re-read if the registry ever gains a multi-shot workhorse.

**One additional binding.** A2's registry ties each route to the prompt-pattern version it was validated against. So A3's skill bundles must carry a version stamp, and that stamp is recorded on every generation in the media-job ledger — which is what makes "did the last prompt change actually help" answerable, and is the same requirement C5 imposes for judge and rubric versions.

### 3.2 The one unified en/cs video pipeline fork

Three briefs constrain the same fork: A2 (Veo native audio is English-first; Czech speech unreliable), A4 (Czech equals silent video plus Czech TTS overlay, or subtitles only; model-native Czech speech banned in v1), C6 (script-lock as the primary control; unattended spoken lines carry no claim tokens). Stated once as a single design:

**Shared spine, both languages.** topic → angle → hook candidates → script (claim-gated) → shot list or slide list → keyframes or slides (approved) → **[fork]** → shared assembly engine (stitch, overlay text composed from verified strings, duck music under voice, loudness-normalise, safe zones, end card, export, sign) → master plus per-platform derivatives → pack.

**The fork has exactly two axes.** Visual source: generative clips (image-to-video from approved keyframes) or slide-motion (Ken Burns over approved slides). Audio source: model-native speech, TTS voiceover rendered from the verified script, or no speech (music bed plus burned-in captions).

**Three legal recipes in v1.** **EN-A** — generative clips plus model-native English speech. **EN-B / CS-A** — generative clips plus TTS voiceover (ElevenLabs primary, Azure Neural fallback). **CS-B**, the default Czech recipe — slide-motion plus Czech TTS, or subtitles-only plus music.

**Banned in v1.** Model-native Czech speech, in any route. Model-rendered message-bearing text in either language. Model-rendered Czech text of any kind.

**Six enforcement rules that make the fork safe.** (1) Script-lock: audio is a rendering of claim-gated script text; the script is the artefact of record. (2) In unattended runs, spoken lines carry zero claim tokens — no numbers, currency, entities beyond own brands, superlatives or outcome statements; all claim payload lives in burned-in on-screen text composed at assembly time from verified strings, so model improvisation cannot fabricate anything that matters. (3) Caption text always comes from the script verbatim; alignment supplies timing only — and on the Czech path, TTS-native timestamps remove speech recognition from the caption path entirely, which matters because A4 measures Czech word error rate at roughly two to three times English. (4) Speech recognition runs as a *sampled adherence monitor* — did the model say what it was told — never as the per-asset gate; a measured adherence drop disables audio for that route. (5) Fail-closed: if the Czech TTS provider or voice is unreachable, degrade to subtitles-only plus music; never fall back to model-native Czech speech. (6) Disclosure is triple: a burned-in human-perceivable AI label at render time (the load-bearing control), platform-native label flags set at publish-prep, and a signed C2PA manifest archived with the pack and never relied on for compliance.

**The one thing the fork does not fix.** Postiz exposes no AI-label fields (C1), so step (6)'s platform layer is a manual human action in v1 and belongs in the runbook and the pack checklist.

### 3.3 C6's refinement of D-03 — the live site wins on commercially binding facts

D-03 locks a flat precedence order: Notion MCP primary → theme config → live public website verification. C6 demonstrates that this default is right for internal knowledge and **wrong for commercially binding facts**, because the live site is the thing a prospect can actually read an hour before seeing our post. Precedence is therefore per fact class: the site is binding on price values, trial terms, plan contents, guarantees, discount and affiliate terms, offer availability, and CTA destination liveness; Notion is primary on identity, offers, capability statements, ICP map, claim ledger and proof allowlist; config is primary on CTA selection, pricing policy, product rules, voice rules, visual baseline and compliance policy.

Three asymmetries are load-bearing and must survive into the architecture. **Excludes are monotonic** — any source saying "never say X" wins permanently for that run, and no precedence rule may remove an exclusion. **The site can subtract but never add** — if our own site no longer mentions a feature, that invalidates a capability claim; but our own marketing copy is never *evidence for* a claim, or the system would bootstrap its own puffery into approved truth and any hallucination that ever reached the site would become permanent. **Silence is not agreement and unreadable is not disagreement** — a source that does not mention a fact reduces corroboration; a failed fetch is recorded as "not observed", never as "site disagrees", because collapsing those two turns a flaky network into a false red flag and trains the operator to ignore alarms.

And the red-flag rule: disagreement inside the commercially binding set is never tie-broken. Publishing one of two possibly-wrong prices is a commercial promise and a trust event; not posting today costs almost nothing. The correct output of "our two systems of record disagree about our price" is an alert to a human — which is independently useful, because it means the operator's own house is out of sync. **Logged as a refinement of D-03.**

### 3.4 The exemplar corpus is style only, never facts — a standing normative rule

The local corpus is dense with other people's commercial claims: twelve demos in five days, 25–40% response rates, 300 leads from one search, seven figures added in a quarter, twelve-plus hours saved weekly, "Guaranteed." C5 correctly uses this corpus as the few-shot grounding for the English voice rubric — which is exactly why it is also the highest-probability fabrication source in the system: the generator is being shown these numbers as examples of good writing at the precise moment it writes.

**Normative rule, binding on every later author.** The exemplar corpus feeds **style retrieval only**. It is excluded from any retrieval path that answers a factual question, and the claim ledger is never populated from it. A dedicated **corpus-leakage check class** compares generated numbers, metric phrases and named entities against corpus content and blocks any overlap lacking a claim-ledger entry, recording a leakage event as a signal that the few-shot design is bleeding facts. Where an exemplar's *structure* depends on a metric, the pattern is abstracted before use — "open with a specific outcome number" is a structural instruction; the number itself is not carried.

C5's voice-side half of the same wall stands alongside it: borrow the craft (hook construction, specificity, personal stake, rhythm, honest structure), reject the tone and the CTA mechanic. Several of the corpus's best-performing posts use hype absolutism and gamified hard CTAs that this project's own rules forbid, and calibrators must be told this explicitly so "but the real post did X" cannot be used to argue down a legitimate flag. The operator already applies this discipline manually — the GTM playbook tags every third-party figure as *their* claim with a distinct marker — so the system is formalising an existing instinct, which is the easiest kind of control to get adopted.

### 3.7 Postiz — positive findings are paper claims

C1's findings are genuinely encouraging: draft status with no schedule date, drafts that persist in the calendar until a human acts, complete feature parity between cloud and self-hosted, 28-plus connectors covering every List B destination, an officially supported MCP server, and a $29 cloud tier. **Every one of these is a documentation claim.** No Postiz account exists (OP-2), so nothing has been verified against a real plan.

The fallback ladder must be designed first-class rather than as an afterthought: unscheduled draft (primary) → far-future scheduled post (low friction, requires a date change before publish) → local-only staging with manual per-platform paste (high friction, always available). Note also that D-04 sets the priority explicitly — prove the research-to-assets pipeline first, distribution later — so the Postiz trial is deliberately downstream of the media trial, and the architecture must remain publishable-by-hand in the meantime.

### 3.10 Two capacity conflicts — cost model and review throughput

**Cost model.** C4's forecast uses illustrative figures — about $2.50 per reel, $0.50 per carousel — while A2's verified pricing gives roughly $1.35 per finished standard-tier reel including retries and about $0.49 per language for seven images. A2 owns provider facts. **Resolution: the forecast engine reads prices from the model registry's price snapshots, never from hard-coded numbers**, and displays the snapshot date alongside the estimate. The orders of magnitude agree (five two-language packs land near $19 either way), but the authoritative figure is A2's, and the registry is what keeps the forecast honest as prices drift — Kie cut Veo prices twice during 2026.

**Review throughput.** C4 designs for about five topics reviewed in under thirty minutes. A1 measures operator QA at 20–30 minutes per *finished video*, and 15–20 minutes of daily QA for a batch of auto-generated packs. B3 says the per-run cap should be informed by review capacity. These only reconcile if the binding constraint is named correctly: **video is the bottleneck, not topics.** Resolution: two separate caps. Topics per run tracks C4's five-in-thirty-minutes target. **Media-bearing assets per run is capped separately and much lower** — a default of one to two finished reels per language per run, which lands the weekly total at A1's three-to-five bar. Copy-and-carousel-only topics can exceed that cap freely because their review cost is minutes, not half-hours. This also gives B3's max-items rule a concrete shape it lacked.

### 3.11 The review UX assumes affordances that D-07 and C3 do not fund

C4's walkthrough describes a browser experience with live buttons — "APPROVE & GENERATE", per-topic toggles, feedback forms, "Generate at 2 PM today". D-07 locks the review model as "human reviews packs manually in an organized output folder", C3 designs a console process with no server, and C2 confirms the app is a scheduler-agnostic console application whose only observability in a scheduled context is file logging.

**Resolution.** The run digest is a **static HTML or Markdown file inside the run folder**. It may look like a dashboard — headers, tables, bands, cost breakdown, dedupe notes — but nothing in it is live. Approval is expressed by one of two mechanisms: editing a decision file that lives beside the digest in the run folder, or running an interactive console command referencing the run id. No web server, no local service, no session state in v1. C4's decision *content* (what the operator must see and decide) is fully adopted; C4's interaction *mechanism* is replaced. If a small local review UI is ever wanted, it is a later phase with its own decision, not an implied requirement of this design.

### 3.12 Czech voice quality — A1's pessimism versus A4's evidence

A1 flags Czech voiceover as a material constraint, citing roughly 15–20% lower prosody accuracy than English and recommending fallbacks including English audio with Czech subtitles. A4 finds ElevenLabs Czech to be production-grade, evidenced by a live Czech government deployment handling around 5,000 calls a day, with Azure Neural cs-CZ voices as a mature cheaper tier.

**Resolution: both are right about different things.** A1's pessimism applies to **model-native speech generated inside a video model**, which A2 independently confirms is English-first with unreliable non-English output. A4's optimism applies to **dedicated text-to-speech providers**, which are a different product category with far better Czech coverage. The design consequence is exactly the fork in §3.2: Czech never uses model-native speech and always uses dedicated TTS or no speech at all. A1's proposed fallback of "English audio with Czech subtitles" should be **rejected** — under D-02 it would produce a Czech asset that is audibly English, which is precisely the translated-feeling output F-7 exists to prevent. The correct Czech degradation is subtitles-only plus music, not English audio.

### 3.13 B5 versus B1 on TikTok, and the build-versus-buy line

**The correction.** B1 placed TikTok Creative Center at P1-narrowed, monthly manual browse, "public/business-login UI only". B5, fetching a July-2026-dated source, finds the situation has tightened further: **the Trends analytics modules now sit behind a TikTok for Business login**, and only the Top Ads gallery remains browsable logged out. B1's *stance* survives unchanged — monthly human ritual, no engineering spend — but the *reason* hardens: it is now a login-walled surface, which the project's own permanent rule ("no login-walled scraping ever, including cookie-lending schemes") puts permanently beyond any automated fetcher, not merely beyond a polite one. A human logging into a free business account and reading is ordinary use and remains fine.

**The consequence, and the genuinely new architectural idea in B5.** If the only remaining automated eye on short-form trends cannot be built, it must be bought or done without. B5's verdict is **buy on top exactly where platforms are closed; keep building only what is free and officially open.** That line is worth stating as a standing principle, because it generalises: a collector we are not permitted to build is not a gap to engineer around, it is a make-or-buy decision with a third option (do without, and say so in the pack).

**Resolved recommendation, trial-gated.** Adopt Virlo Starter at $49/month for the short-form trend axis, **pending a one-week free trial that must answer three questions**: (1) is full MCP/API access genuinely included at the Starter tier — B5 found a direct conflict between Virlo's own March 2026 MCP guide ("any paid plan includes full API access") and its pricing page (which lists API access as an Enterprise bullet), and this single fact gates the whole adoption; (2) does a niche monitor pointed at AI tools, coding agents and AI-sales content produce outliers that beat what the free portfolio already surfaces — Virlo's marketing is consumer-creator and its fit for this theme is genuinely unproven; (3) what are the actual, unpublished rate limits. Shortimize is the named fallback in the same category, evaluated at the same gate. If both fail, the degraded state is designed rather than broken: the short-form trend axis reverts to the operator's monthly Creative Center ritual and the pack says so.

**Two honest caveats to carry.** Virlo shows no evidence of CZ or regional trend filtering — assume global-English, which means the short-form trend axis contributes to the English output set and only indirectly to the Czech one, consistent with §2a's finding that Czech signal is structurally thin. And Virlo's *upstream* collection from TikTok, Instagram and YouTube is undisclosed and cannot be platform-licensed, because no such licence programme exists. B5's position — that consuming a vendor's **derived analytics** is a materially different posture from buying **raw scraped passthrough** (the TikHub and twitterapi.io class both B2 and B5 exclude), and is the same posture as using Exploding Topics or BuzzSumo — is reasonable and is the working assumption. It is also exactly the kind of reasoning that deserves one paragraph from C7 rather than a shrug, so it is carried as an open item.

**Vendor churn is now a named, evidenced risk class.** Trendpop, a TikTok trend tracker, is dead as a standalone product — its domain redirects to an acquirer. F-3's model-churn logic therefore applies to *data vendors* as well as to models: the source layer must be designed so a licensed vendor can be swapped without redesign, every licensed source must carry a designed degraded state under B2's ladder grammar, and vendor records belong in the same registry discipline as model routes, with last-verified and recheck-by dates.

**The trap list is settled and should not be re-litigated by later authors.** BuzzSumo (its API sits behind a $999/month enterprise wall), Tubular Labs (enterprise, media-company ICP), TrendHunter (consumer-product ideation, wrong niche), Treendly (stale-data class, no verified export), Trendpop (dead), Kalodata (TikTok Shop e-commerce, wrong niche), Exolyt (about $400/month for one platform), TikHub-class raw-data APIs (unofficial scraped passthrough, excluded by the legitimate-access principle), Mention (opaque pricing behind a sales call), and the enterprise listening suites B1 and B2 already dispositioned. Brand24 is the one genuine near-miss — the cheapest legitimate route to mention-level coverage including a Reddit-shaped signal — but at $199–448/month with the API add-on it is a second-tenant decision, not a v1 one, and it does a different job (watching *your keywords being mentioned*) from a trend platform (watching *what is rising*).

### Viral AI video generation — tools, prompts/skills/agents, workflows, recommendations for this project

**The bar, and the honest quality floor.** Short-form video is the competitive minimum for B2B in 2026, not an experiment: A1's benchmark data puts the bar at three or more native videos per week, with medium polish beating low volume at high polish. But roughly 30–40% of first-pass AI video output still shows obvious flaws — motion ghosting, character morphing across cuts, warped or hallucinated on-screen text, synthetic-sounding voiceover. The quality floor has risen enough for medium-polish B2B content; it has not risen enough to remove the operator QA gate. Plan for 20–30 minutes of human review per finished video, which is the real throughput constraint on the whole system.

**What actually works, and what fails.** Hooks decide the outcome in the first one to three seconds: problem-first, curiosity gap, visual contrast, or pattern interrupt. Pacing sits at roughly half a cut to one and a half cuts per second for B2B, aligned to narrative beats rather than arbitrary intervals. Finished lengths cluster short — 15–35 seconds is the sweet spot across TikTok, Reels and Shorts, against hard caps that are far higher. Loop readiness is rewarded on vertical platforms. The B2B-safe adaptation of consumer virality is to keep the mechanics (contrast, specificity, transformation) and drop the exploitation (fake scarcity, invented urgency, sensationalism). The reliable narrative shapes are before/after, stacking, versus-contrast, and a short story arc. The hybrid faceless-plus-UGC pattern is the current B2B consensus — roughly 60% screen or product footage, 30% b-roll or graphics, 10% text callouts, with conversational first-person narration and a real dashboard or artefact shown as proof.

The failure list is equally concrete and forms the rejection rubric: visible motion trails, features changing between cuts, parallax that does not match camera logic, plastic-looking compression damage, frame-rate stutter, any on-screen text character that is unclear at mobile scale, and any metric stated without visible proof. On-screen text is the most reliable single tell, which is why the rule below is absolute.

**Providers and models — the resolved recommendation.** The evaluation mandated Kie.ai and Higgsfield.ai. Kie.ai is a prepaid credit-based API router: one balance, one API surface, many upstream models at roughly 30% below official pricing (60–70% on selected routes). It is legitimate and aggressively priced but not SLA-grade — Trustpilot around 2.5 on a small pool, recurring reports of credits consumed on stuck tasks, tightening content filters. Treat it as a **replaceable routed dependency behind a provider abstraction**, which is precisely what the routing-contract axes and model registry exist for.

Recommended roster on Kie: **Nano Banana 2** as the everyday image model at about four cents per image, **Nano Banana Pro** at about nine to twelve cents for finals that carry on-image text, **Veo 3.1 Fast** as the video workhorse at about thirty cents per eight-second clip with native audio, **Veo 3.1 Quality** at about $1.25 reserved for one or two hero assets, **Seedance 1.0 Lite** as a five-to-eight-cent motion preview before committing to the good model, and **Kling 3.0** as the registered alternate and the only multi-shot-native route. **Sora 2 is excluded everywhere** — OpenAI switches the API off on 24 September 2026, which is also the standing proof that no model may ever be hard-wired. Suno-routed music is forbidden for published assets: no official Suno API exists, every route is unofficial, and the upstream is in active litigation. Licensed library music or a paid-plan AI music generator is the correct source.

Higgsfield.ai is evaluated on paper only, no account. It is a well-funded creator and marketing studio aggregating the same underlying models Kie routes, plus genuinely differentiated own tooling — cinema-style camera controls, character-consistency identity, a UGC builder, a marketing studio that turns a product URL into ad formats — with MCP integration and editor plugins. But its economics are subscription-plus-expiring-credits rather than non-expiring pay-per-use, its API documentation is materially thinner than Kie's, and its differentiators are human-studio features that do not fit an unattended pipeline. **Recommendation: ignore for v1 as an API route; optionally buy a personal seat as a review-and-polish studio entirely outside the automated pipeline.** The genuine alternative worth registering is **fal.ai** as a fallback router with a better engineering reputation at somewhat higher per-clip cost, with a documented migration path to Google's direct API when SLA and indemnification start to matter more than a three-to-four-times price difference.

**Model and job fit.** Image-to-video, keyframe-first, is the default workflow and the single most important economic decision in the pipeline: generate and approve a four-cent keyframe carrying the brand colours and correct text, then animate it. This decouples the expensive spend from the brand-correctness decision and lets one composition serve two languages. Text-to-video is permitted at draft tier only. First-and-last-frame generation produces transitions and seamless loops. Reference-to-video holds a product consistent across clips. Multi-shot-native generation is a hero-tier experiment, never the scheduled default.

**Prompts, skills and agents.** Strong practice is not one clever prompt but a short assembly line of narrow, checkable steps, each with a four-part anatomy: role and constraint framing, grounded inputs the model is allowed to draw on, the generation instruction with an explicit output shape, and a self-check rubric the model applies before the output is considered done. That anatomy repeats across hook, script, shot list and on-screen-text steps. Hooks are the one artefact worth overgenerating — three to five candidates with a selection rubric, because text is free and video is not. Scripts fill a beat scaffold (hook → problem → turn → mechanism → soft CTA) rather than free-writing. Shot lists draw from a constrained shot-grammar vocabulary and now carry a keyframe reference per row, which is a stronger continuity mechanism than repeating a description.

Negative prompting is five composable layers, not one flat list: engine-level visual artefacts, engine-level copy slop, theme-specific exclusions, language-specific slop lexicon, and route-policy constraints pulled automatically from the model registry (person-generation restrictions in Europe, refusal of named real people, trademark-in-input refusals). A **brand lock** — identity anchor, visual baseline, voice descriptors, claim boundaries, CTA policy — is a structured fact set injected identically into every step rather than prose repeated everywhere. Four reusable skill bundles cover the mandated workflows (reels scripting, ad creative, UGC, carousel), each holding instructions, exemplars, a rubric and a fallback. The engine/theme/language boundary follows one test: if changing it touches more than one theme, it belongs to the engine; language is its own third axis so every Czech-writing theme shares one Czech lexicon.

**Assembly is where quality is actually won.** The unowned middle — between raw clips and a publishable asset — is a deterministic template job, and owning it locally on an FFmpeg-core engine costs effectively nothing per asset, runs identically on both target platforms, and removes a third-party outage from the nightly critical path. It stitches, applies overlays, mixes voice over a ducked music bed, normalises loudness to −14 LUFS integrated with a −1.0 dBTP ceiling, composes inside a universal safe box of roughly 900×1400 within the 1080×1920 master, adds a two-second end card with a dual-delivery soft CTA, exports per-platform derivatives by layered re-composition rather than cropping, and signs a C2PA manifest at export. **Never ask a generative model to render message-bearing text in either language** — captions and titles are stamped on afterwards with bundled fonts verified for full Czech glyph coverage, which makes displayed-text accuracy 100% by construction and lets text be edited or re-languaged without re-generating video.

**The Czech fork, stated plainly.** English may use the video model's own generated speech. Czech may not — model-native non-English speech is materially weaker, and the design bans it. Czech is produced as silent visuals plus dedicated Czech text-to-speech (ElevenLabs primary, with production evidence in Czech; Azure Neural cs-CZ as the cost tier), or as subtitles plus a music bed. **Carousel-to-reel is the default Czech video recipe**: Ken Burns motion over approved slide art, our own typography, Czech TTS or subtitles, no generative video model in the loop at all. It is the safest Czech format available, the cheapest per asset, and it sidesteps both the spoken-claim and diacritic risks entirely. Czech short-form also targets different destinations — LinkedIn and long-form YouTube rather than TikTok — because Czech B2B decision-makers read entertainment-styled short-form as cheap.

**Quality rubric and rejection handling.** Accept or reject on: motion integrity (no trails, no morphing, parallax consistent), compression and detail, text legibility at mobile scale, audio prosody and pacing, voice-to-visual timing, absence of uncanny artefacts, hook effectiveness in the first three seconds, claim verifiability, and clean loop or ending. Each rejection type has a named next step: motion glitches get a stricter consistency lock or an alternate route; audio problems get a different voice or provider, never a switch to the other language; text problems are never fixed by regenerating video with text; unverifiable claims are fixed in the script, not the render. Refusals are normal outcomes, not errors: one sanitise-and-rewrite, one model swap, then degrade to plan-only with the reason packaged for the human, capped at three paid attempts per asset slot.

**Operator workflow and what may run unattended.** Idea and angle, script approval, and final QA remain human. Topic research, script and shot-list drafting, keyframe generation, motion drafts, packaging and audio-QA flagging can all run unattended within budget caps. Media spend escalates a tier only through an approval event, and hero tier is never auto-selected. Draft creation in the publishing bridge may be automated only when config explicitly enables it, and live publishing never is.

**Economics, honestly.** A finished two-language standard pack costs about $3.80 in generation. The $50 trial buys roughly thirteen such packs — enough to validate the architecture and the quality bar, not enough to run a month of production, which at three runs per week lands near $90–140 per month. The single largest cost lever is not model choice but the language-neutral-footage-plus-per-language-overlay recipe, which collapses the Czech video multiplier, and the keyframe-approval gate, which keeps rejected work at four cents instead of thirty.

**Recommended trial plan:** about $8 on a bake-off producing the operator's own evidence rather than blog claims (the same three prompts through Veo Fast, Kling 3.0 and Seedance, plus the image trio), about $35 on eight to ten real two-language packs end to end, about $7 held in reserve for retries and one hero reel.

### Viral topic extraction sources, methods (including Playwright where justified), ranking, and guardrails

**The 2026 access reality, stated first because it reshapes everything.** The open web where a script could quietly read Reddit, X or TikTok is gone. X ended its free read tier and now charges per request. Reddit closed self-serve commercial access in late 2025 and deprecated its unauthenticated JSON endpoints in May 2026, and is actively litigating against scrapers. LinkedIn litigated a $10M-revenue scraping company out of existence and continues removing company pages of automation vendors. Anti-bot vendors now combine TLS fingerprinting, hardware-environment verification and behavioural machine learning; detection of stock headless browsers on protected surfaces is effectively immediate. Buying a bypass does not improve the contractual position — circumvention of technical measures is itself a named violation on the surfaces that matter.

**The good news is bigger than the bad news.** A genuinely strong research portfolio is available on day one, free, with no legal risk: **Hacker News** (two official free APIs, no key, permissive robots with a 30-second crawl delay — the single best free source in this niche and the anchor of the roster), **AI newsletters** (a free human editorial layer that partially compensates for the X gap), **Product Hunt**, **Hugging Face**, **Bluesky** (the only fully open real-time public social firehose in 2026), **Google News RSS** (including Czech locale), and **YouTube's Data API** (10,000 units per day, key issued same day). Plus the sleeper hit: because of the Digital Services Act, **every ad delivered to EU users — including Czech users — sits in a public searchable archive**, Meta's with an official API and LinkedIn's with no login at all, exposing competitor hooks, offers, targeting parameters and impression ranges aimed at exactly this market.

**Signal types and which sources serve them.** Launch hype is excellently covered (Product Hunt, Hugging Face, newsletters, Google News). Viral discourse is well covered with an X-shaped hole largely filled by relay (Hacker News, Bluesky, newsletters — a six-to-twenty-four-hour delay that is immaterial at a human-gated cadence). Ad creative patterns are well covered including Czechia (both ad libraries). Search demand is adequately covered manually (Trends UI and CSV, Keyword Planner). Short-form format trends come from a monthly manual browse of TikTok's Creative Center. **ICP pain is the one genuine day-one gap** — the axis Reddit serves — and it is also the slowest-decaying signal, so losing it for a few weeks costs breadth of evidence rather than timeliness.

**Extraction method per source.** The method vocabulary is official API, feed, licensed vendor, auth-integration, MCP wrapper, operator input, or skip. Hacker News, Product Hunt, Hugging Face, Bluesky, YouTube and Podcast Index are official APIs. Tech press and vendor blogs are conditional-GET feed polling with snippet-and-link storage rather than article bodies. Meta Ad Library is an auth-integration through the operator's verified Meta identity, gated on a personal government-ID check and 60-day token renewals. Google Trends, LinkedIn (organic and Ad Library), TikTok Creative Center, review sites and community platforms are operator input. Reddit is operator input via Reddit Pro plus manual thread curation. X is skipped. An MCP wrapper is acceptable only when it fronts a legitimate method — the transport does not launder the method.

**Where a collector may not legally be built, buy on top or do without.** This is the third option the assignment's framing does not name, and it is the right answer for the closed short-form platforms. TikTok has no legitimate programmatic read path and none is coming — the Research API is vetted-academics-only, the Commercial Content API is ad-transparency-scoped, the "API" advertised on the Creative Center is a generative ad-production tool rather than a data-out surface, and as of July 2026 even the Trends analytics modules require a business login. Instagram's only official door is narrow by design: hashtag search over a watchlist you already chose (30 unique hashtags per rolling seven days) plus business discovery on named competitor accounts, through the operator's own business account — it can validate but never discover. YouTube is the best of the three and stays a built collector: search at 100 units per call is the niche radar, the most-popular chart is one unit per call and works per country including Czechia, and a realistic daily budget of niche searches plus cheap reads plus two chart pulls consumes well under 10% of the free 10,000-unit quota.

So the short-form trend axis is **bought**: a licensed trend-intelligence vendor (Virlo Starter, $49/month, covering TikTok, Reels and Shorts with daily refresh and keyword-defined niche monitors), adopted pending a one-week trial that must confirm Starter-tier API access, real signal quality for AI and B2B topics, and the unpublished rate limits. The demand axis is likewise bought from a data vendor (DataForSEO, roughly $10–15/month) with the manual Trends CSV path retained as the designed degraded state. Both speak MCP with non-interactive key auth, so the collector layer standardises on **MCP as the integration idiom for licensed data** while keeping bespoke collectors for the free open APIs — and both carry a **credit budget metered like money**, with free re-reads of already-computed results rewarding the cache-before-call discipline. Two free alert services (Talkwalker Alerts over RSS and email, Google Alerts over email) and two free operator tools (a YouTube outlier finder, a Trends-augmenting browser extension) round out the layer. Total new recurring spend is about $60–65 a month, which replaces precisely the two collector families that would have been the most fragile and the least defensible to build. The evaluation lens that sorts this market is one question — *do the vendor's terms permit its output to feed our pipeline?* — and the answer divides it cleanly: derived-analytics vendors almost universally permit internal use and forbid redistribution, which is exactly our pattern (insights in, our own original content out); raw-data passthrough APIs are the excluded class, because there the vendor absorbs technical risk without changing our compliance posture. Vendor churn is real and evidenced — one named TikTok tracker died mid-2026 and now redirects to its acquirer — so every licensed source carries a designed degraded state and a swap path, exactly as every model route does.

**On Playwright specifically, since the assignment asks.** Browser automation is justified in the v1 collection path **essentially nowhere**. Every major surface is either officially accessible (use the API), officially closed and defended (do not scrape), or reachable by plain HTTP where a browser adds nothing. Playwright therefore stays in the stack only as a per-source, explicitly-approved future exception mechanism for genuinely open sites with no feed and no anti-bot, plus two uses with no third-party ToS exposure: verification fetches against our own public pages, and screenshot capture for QA. This is not timidity — it is the recognition that a headless browser aimed at a defended surface produces banned accounts, burned IP ranges and legal letters rather than data, and that the operator's own Meta business accounts and LinkedIn company page are real assets at risk.

**The do-not-scrape list, binding in every mode including degraded ones.** Reddit (any surface, including mirrors). X (any surface). LinkedIn (any surface, logged in or public — permanently, and note that holding a company page makes scraping the operator's own contractual breach). Meta and Instagram web surfaces including the Ad Library UI — use the API and human eyes. TikTok, including Creative Center. Google SERP and Trends web surfaces. G2-class review platforms. Any login wall, including cookie-lending schemes. Any surface serving an anti-bot challenge — a challenge is a "no", logged and skipped, never solved. Any robots-disallowed path. Absence from this list is not permission; new sources enter through the method-evaluation gate.

**Fallback ladders and unattended mechanics.** Every source has a ladder — primary, degraded, operator-supplied, skip-with-log — and no rung ever falls through to scraping. Skip-with-log always records source, rung attempted, error class, timestamp and an impact note for the pack; two consecutive failures raise a source-health flag; three open a maintenance task rather than silently degrading forever. Unattended collection is window-keyed and idempotent: a run is identified by its logical collection window, a second firing inside the same window resumes or no-ops rather than producing a competing pack, a single-holder lease guards the window, and all collection writes are append-only under natural keys so replay cannot double-insert. Rate limits are respected with declared per-source budgets, Retry-After honoured, exponential backoff with jitter otherwise, per-source circuit breakers, and a global wall-clock ceiling so ranking and packaging always run on whatever was gathered. Feeds use conditional requests so most polls cost a 304. Paid endpoints are cache-before-call. Pagination prefers cursors, snapshots list endpoints before detail fetches, and caps depth.

**Poison pills, in two senses.** Structurally: per-item size caps, timeouts, content-type and encoding validation, quarantine of malformed items with raw bytes retained — one bad item never kills a source, one bad source never kills a run. Semantically, and more importantly: **all collected text is adversarial input that will later sit inside model prompts.** Prompt injection through a crafted title or feed entry is a live hazard. Collected content is carried as quoted data with provenance tags, never as instructions; the instruction layer stays structurally separate and privileged; and injection-style phrasing in a source item is itself a veto signal rather than something to pass through.

**Raw artifacts and retention.** Every topic candidate carries provenance a human can click and check. Request logs are always stored (12 months — compliance memory, small). Raw payloads are stored briefly (30 days, adopting the strictest per-source rule as the global default). Normalised signal records live 90 days, long enough to compute velocity and to analyse which sources produced winners. Provenance snapshots — canonical link, the minimal quoted excerpt that triggered candidacy, retrieval time and method — are retained permanently with the pack, precisely because they carry links and excerpts rather than payloads. Full article bodies and media files are never stored; links and excerpts only. And because public social content is personal data under GDPR regardless of pseudonymity, author handles are minimised or hashed, and targeted deletion by canonical key must exist from day one.

**Ranking.** Raw signals become scored candidates on four dimensions — attention/virality, brand fit, freshness, and a confidence weight reflecting what the source actually exposed — combined **multiplicatively** rather than as a weighted sum, so that a near-zero brand fit cannot be outvoted by a large virality number. That is the mathematical backbone of "weak brand fit → skip". Virality is normalised *within each source's own recent distribution*, never compared raw across sources, and only sources that expose counts and retain history can produce a percentile at all: sources that expose only list position get a capped proxy, and human-curated items get an operator salience input labelled distinctly and never rendered as measured virality. Corroboration is counted across structurally distinct **source families**, not source instances, because the day-one roster is heavily correlated on launch news. Freshness decays by signal class — spike, rising, launch-hype, ad-creative-pattern (whose age term is *inverted*, since a long-running ad is a proven ad), and evergreen-pain (which decays over months and is really governed by whether the angle was covered recently).

Two independent gates run before anything is written. A **numeric floor on brand fit alone**, applied before the composite, so that a fit problem is never confused with ordinary staleness. And a **binary veto list** sitting outside any average — legal and claim-risk topics, competitor disparagement, high-severity controversy, detected manipulation, prompt injection — which cannot be outweighed by any score. Seven negative brand-fit criteria are enumerated with a rules-first, LLM-second split: category mismatch, competitor saturation, tone and controversy risk, the "brand looks desperate" pattern, legal and claim risk, off-ICP audience mismatch, and stale consensus. The brand-fit judgment must state the honest connection in one sentence or explicitly fail — making the *attempt to connect honestly* the test itself — and if the judgment step cannot run at all, the candidate fails closed to monitor-only rather than defaulting open.

Czech and English are ranked separately, and Czech is ranked by a different formula: because none of the four global Czech-signal carriers exposes per-item engagement, the Czech composite drops the virality factor rather than proxying it, and every Czech candidate is labelled as resting on English-observed discourse plus local demand and ad signal. Without this, the Czech output set would be suppressed by arithmetic and D-02 would fail silently.

**Guardrails on the human side.** Every candidate carries an inspectable scorecard readable without statistics literacy: sub-scores plus plain bands plus one sentence of rationale per dimension, the sources that fed it, the evidence-quality label, the gate status with the specific skip reason, the per-language outcome, and the ranking-config version that produced it. Rejections are reason-coded so that "the topic was wrong" is never conflated with "I had enough content this week", and only ranking-relevant reasons feed calibration. Thresholds are versioned and dated, and any proposed loosening of the brand-fit floor requires a logged human rationale — a governance rule that exists specifically to block the failure mode where thresholds quietly relax over months to hit a volume target.

**Scheduled collection behaviour.** Cross-day dedupe keys on a normalised semantic topic identity, not text match, and the resurfacing decision is a matrix over trajectory, prior-pack state, and whether the underlying discourse materially changed — rising and never generated ranks normally; rising and already generated resurfaces only with a detectable new angle; declining and already generated is suppressed permanently. Max items per run is applied after filtering as a top-N of passing candidates per language, never by lowering the threshold to fill a quota, and a second, much lower cap applies to media-bearing assets because video review is the real bottleneck. Missed windows are skipped rather than backfilled — re-researching what was viral three days ago is both stale and a burst of unplanned paid runs. Cold start is a data-availability state, not a separate code path: with thin sources the corroboration bonus rarely fires, evidence is labelled honestly as thin, operator-seeded topics pass the identical gates, and a run producing few or zero passing candidates is a correct outcome to show the operator rather than a failure to hide.

## 7. Open-decision list for W2.5 — the human checkpoint

Each item states the options and this synthesis's recommendation. Items 1–8 are the conductor's named list; 9–17 are the further decisions the briefs deferred to a human.

**1. X reads — reopen on the new first-party fact?** *Options:* (a) keep D-08 closed for v1; (b) reopen at v2 with a hard monthly cap; (c) reopen now. **Recommendation: (a), with a measurable v2 trigger.** The operator rejected a *reseller*; X's own metered pricing ($0.005/read, ~$50/mo at 10k reads) is a different instrument and is contractually clean, so the reopening would be a budget decision rather than a compliance one. But the honest damage assessment is low: at a human-gated daily-to-weekly cadence, a 6–24 hour relay delay through Hacker News, newsletters and Bluesky is immaterial. Trigger for revisiting: after four weeks of real runs, if the share of packs anchored on sub-24-hour signals is persistently near zero *and* spike-class response is judged commercially important.

**2. Reddit ritual sign-off.** *Options:* (a) Reddit Pro plus a weekly curated-inbox session; (b) pursue the commercial API contract; (c) buy a licensed listening suite; (d) drop Reddit. **Recommendation: (a).** B1, B2 and C7 converge completely. What the operator is actually signing is three things: that the weekly 30–60 minute ritual will happen and a staleness flag will appear when it does not; that the GDPR obligations attach even to human-written notes quoting a person (extract-first storage, bounded retention, hashed usernames, a written legitimate-interest assessment and a published privacy notice as company artefacts); and that month-one packs will honestly label the pain axis as operator-fed. (b) becomes a deferred trigger at multiple paying tenants; (c) is a v2 question priced at $199–448/month; (d) is rejected — the GojiBerry evidence says this niche's richest pain signal lives there.

**3. Stack confirmation (OD-5).** *Options:* Python, Node/TypeScript, .NET. **Recommendation: confirm Python and close OD-5.** C2 verified parity on MCP and LLM SDKs, a materially better realistic Windows distribution story, a stronger data/ranking ecosystem, and an Anthropic-SDK MCP bridge; the only Node edge (Playwright nativeness) is immaterial at this concurrency, and Playwright barely features in v1 anyway.

**4. Higgsfield role (OD-3).** *Options:* H1 ignore for v1; H2 human-side complement (personal seat outside the pipeline); H3 second routed provider. **Recommendation: H1, with H2 optional at the operator's discretion.** Kie routes the same underlying models more cheaply with far better documentation; Higgsfield's genuine differentiators are human-studio features that do not fit an unattended pipeline; and H3 is blocked by sparse API docs, unknown per-generation pricing, expiring credits and opaque moderation. H2 costs $17–39/month, has zero architectural impact, and may genuinely help polish a winning draft.

**5. Claim-ledger location (C6 D-d).** *Options:* Notion, theme config, or split. **Recommendation: split, with Notion primary.** C1 confirms a Notion typed database can express provenance, evidence pointer, validity window, per-language text and usage scope and is queryable by REST property filters — and it is editable by a marketing-literate operator without touching config. Config carries a pointer plus the design-time policies (pricing policy, compliance obligations). **The one exception is hard excludes**, which must exist in both because they are monotonic and must be enforceable when Notion is unreachable: config holds a baseline, Notion may add, the union wins.

**6. FFmpeg licensing and distribution (A4 D3).** *Options:* bundle a GPL build (x264/x265 enabled); bundle an LGPL build and use platform/hardware H.264 encoders; require a managed install per OS. **Recommendation: require a managed install of a pinned FFmpeg version on both platforms for v1, and do not distribute binaries with the app.** Invoking FFmpeg as a separate process is low-risk even for a GPL build; *distributing* binaries is what triggers source-hosting and notice obligations, and a solo operator does not need that obligation in v1. Pin the version identically on both platforms and bundle the fonts (not the codecs) to preserve rendering parity.

**7. Notification channel (C3).** *Options:* email; chat webhook; desktop notification; filesystem flag only. **Recommendation: filesystem status flag as the mandatory always-written baseline plus email as the default push channel**, with a chat webhook as a config alternative. Email works from an unattended machine with only outbound network and suits a nightly-report rhythm; a webhook is faster to notice but adds a third-party dependency and its own secret. Desktop notification is rejected as a primary channel — it only works when someone is at the machine, which is definitionally false for overnight runs. A notification-delivery failure must never change the run's exit class.

## 8. What changed versus the assignment's assumptions

An honest account of where the research moved the ground under the brief. None of these invalidate the assignment's goals; several change how those goals must be met.

**1. List A's P0 social trio is largely inaccessible.** The assignment's primary candidates were X, Reddit, and a bucketed "web AI/tech news". Two of the three cannot be read by software in 2026: X's free tier is gone and D-08 closed the paid path, and Reddit has no legitimate automated route at this scale. Meanwhile the bucketed third contains the single best free API in the niche. The real P0 anchor set is Hacker News, AI newsletters, Product Hunt, Hugging Face, Bluesky, Google News RSS, and — the genuine surprise — the two DSA-mandated ad libraries, which expose competitor hooks, offers and targeting aimed at the Czech market for free.

**2. Scraping and Playwright play almost no role.** The assignment budgets a full guardrail treatment for browser automation. The honest answer is that Playwright belongs nowhere in the v1 collection path. The guardrails survive in a different shape: a binding do-not-scrape list, a method-evaluation gate for new sources, and a documented reason each major surface is excluded. This is a simplification, not a loss.

**3. Reddit is a human ritual, not an API.** "Curated human input" becomes a first-class source type with its own staleness flag, evidence class and storage rules — an architectural component the assignment did not anticipate, and one that also serves LinkedIn browsing, community reading, Trends CSV exports and operator-seeded topics.

**4. There is a third option between build and skip: buy on top.** Where a platform is closed to us legitimately, a licensed vendor selling *derived analytics* can supply the axis we may not collect. That is the answer for TikTok, Reels and Shorts trends. It also introduces a connector class the assignment did not imagine — an MCP source with a credit budget, async job semantics and vendor-churn risk — sitting alongside owned collectors and the curated inbox.

**5. Video volume norms are higher than implied, and the bottleneck is video review, not topic review.** Three or more videos per week is the competitive bar; 20–30 minutes of human QA per finished video is the real throughput constraint. That forces two separate per-run caps rather than one, and it makes the keyframe-approval gate the most important economic control in the system.

**6. Czech needs its own channel mix, its own video recipe and its own scoring formula.** F-7 anticipated that Czech is not a translation pass. It did not anticipate that Czech would need a *different asset mix* (carousel-to-reel and LinkedIn rather than generative short-form and TikTok), a *different audio path* (dedicated TTS, never model-native speech), and a *different ranking composite* (virality omitted rather than proxied, because no Czech-signal carrier exposes engagement counts). Without that last change, the Czech output set would have been suppressed by arithmetic while every policy document still said it was first-class.

**7. The EU AI Act arrived mid-design.** Article 50's transparency obligations became binding on 2 August 2026 — four days before the briefs were written — with no size exemption and fines up to €15M or 3% of turnover. It converts AI disclosure from a courtesy into a render-time, burned-in, human-perceivable requirement, and the accompanying technical finding (platforms strip C2PA on re-encode) means metadata-based compliance would have failed silently. This is an architecture input, not a legal footnote.

**8. Kie.ai and Higgsfield.ai are not peers.** The assignment names them as parallel candidates. They are different product categories: one is a priced API router with documented async semantics and published prices, the other a subscription creator studio with sparse API documentation and expiring credits. The recommendation is therefore asymmetric — Kie as the router, Higgsfield as an optional human tool — rather than a head-to-head choice.

**9. "Brand spin must be extractable via MCP" collides with unattended authentication.** Notion's hosted MCP cannot survive a 3 a.m. run; the vendor's own non-expiring REST integration token can, and additionally supports the property filtering needed to enforce "unreleased offers are unspinnable". MCP stays for humans; REST does the records. The mandate is honoured, but not the way it was probably imagined.

**10. Provider retention is 14 days and there is no idempotency.** Two facts the assignment could not have known reshape the entire state layer: generated media is deleted after two weeks so re-hosting is mandatory and provider URLs can never be the artifact of record; and no idempotency key exists, so every money-safety guarantee must be built client-side around a write-ahead ledger, with an honest named state for the genuinely ambiguous crash window.

**11. "Always produce plans even without keys" turns out to be the economic backbone, not a fallback.** The assignment states it as a courtesy rule. In practice it is the spine of the tiering model: plan-only is the cron floor, the keyframe is the approval unit, and money only moves after a four-cent image is accepted.

**12. Assembly was unnamed and is where Czech quality is actually won.** The step between raw generated clips and a publishable asset — stitching, our own captions, our own typography, ducked audio, loudness normalisation, safe zones, signing — has no name in the assignment. It costs almost nothing, runs identically on both platforms, and is the single place where the Czech diacritic problem and the spoken-claim problem both disappear.

**13. The publishing bridge cannot carry the compliance flags.** Postiz exposes no AI-label fields, so the platform-disclosure step is a manual human action in v1. That changes the operator runbook and adds a checklist item to the human review gate that the assignment's draft-first model did not contemplate.

**14. Personal data enters through the research path.** Public social content is personal data under GDPR regardless of pseudonymity, which means a legitimate-interest assessment and a published privacy notice are prerequisites the architecture must assume exist — company artefacts the software cannot generate for itself — and targeted deletion by canonical key must be designed in from day one rather than retrofitted.

**15. The naive loop order is wrong in one place.** The assignment's end-to-end loop reads create → package → human decision. The real order puts a cost control before generation: in interactive runs the operator sees a forecast and approves before media spend; in unattended runs the equivalent control is a pre-submission budget cap enforced against the spend ledger, with hero-tier promotion and all publishing still human-gated. Generate-then-review would burn a limited trial budget on assets the operator was always going to reject.

**16. Model and vendor churn is structural, and now evidenced twice.** Sora 2's API dies in September 2026 and a named TikTok trend tracker died mid-2026 and now redirects to its acquirer. Both the model registry and the vendor roster therefore need last-verified and recheck-by dates, a degraded status that stops selection for spend, and a designed fallback per entry. Nothing may be pinned by name without a re-verification cadence attached.
